# 本地笔枢开发计划

## 目标

为个人写作提供一个本地单用户写作台，交互和视觉方向接近线上笔枢，数据始终保存在本机书籍目录中。第一版使用确定性模拟生成器跑通完整创作链路；后续保留 DeterminFlow 适配边界，替换生成器时不改变书籍存档和界面契约。

## 范围

### 第一版包含

- 书架：新建、打开、删除和搜索本地作品。
- 建书流程：书名、立意、题材、风格、篇幅、每章字数。
- 四个前置阶段：世界观、角色表、故事规划、卷大纲。
- 工作台：单章指导、世界干预、写手模式、目标字数和生成进度。
- 正文：章节编辑、保存、历史版本、选段改写、整章润色、重新生成。
- 定稿：模拟后验结算、连续性状态、下一章入口。
- 导出：Markdown、TXT；浏览器直接下载。
- 本地文件存档和端到端测试。
- 模型接入配置：OpenAI 兼容接口、DeepSeek、Ollama 和硅基流动预设，支持本地保存、密钥脱敏和连接测试。

### 第一版不包含

- 账号、云同步、多人协作、计费和公网部署。
- 真实模型生成调用。当前先完成配置和连接验证，模拟生成仍用于无密钥验收。
- 逐像素复制线上登录页或无法公开检查的登录后实现。

## 技术方案

- Node.js 内置 `http` 服务提供静态页面和 JSON API，避免本地安装额外运行时。
- 原生 HTML/CSS/JavaScript 实现界面，采用线上笔枢的暖纸色、墨色、金色和细边线风格。
- 书籍身份是安全的 slug；书籍目录位于 `data/books/<slug>`。
- 长期存档使用 `book.json`、`meta/`、`world/`、`outline/`、`story/`、`archive/`、`cache/` 结构。
- `GenerationEngine` 是唯一的生成边界。第一版挂载 `MockGenerationEngine`，后续可增加 DeterminFlow HTTP 适配器。

## 功能切片与提交边界

1. 项目规则、开发计划和本地脚手架。
2. 书架与本地存档 API：新建、列表、读取、删除和安全路径校验。
3. 建书前置流程：世界观、角色、故事规划、卷大纲的模拟生成和状态保存。
4. 章节生产：单章生成、编辑、版本恢复、润色、后验和下一章。
5. 笔枢风格控制台：书架、世界、角色、规划、正文工作台、助手面板和导出。
6. 端到端验收、使用文档和会话总结。

每个切片都必须有对应测试，测试通过后独立提交并推送到 `origin/main`。

## 验收标准

- `npm test` 通过，覆盖 API 单元测试和完整创作链路。
- `npm start` 启动后可在浏览器打开本地控制台。
- 从新建作品开始，依次完成四个前置阶段，生成第一章，编辑并保存，运行后验，导出 Markdown/TXT。
- 重启服务后书籍、设定、章节正文和历史版本仍可读取。
- 任意用户输入不会造成书籍目录路径穿越。

## 真实 DeterminFlow 接入预留

公开 `bishu-novel` 插件的工作流 ID 默认映射为 `bishu-novel-build`、`bishu-novel-character`、`bishu-novel-story-plan`、`bishu-novel-outline`、`bishu-novel-mvp`、`bishu-novel-polish` 和 `bishu-novel-post-hoc`。后续适配器将通过任务创建接口传入固定的 `workspace_override`，但不把 Core task ID 当作书籍身份。
